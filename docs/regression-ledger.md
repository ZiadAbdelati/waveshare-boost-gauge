# Regression ledger (full history)

The operating manual lives in [../AGENTS.md](../AGENTS.md). This file is the
verbatim chronological record of bugs, experiments, measurements and the
guards they produced; it was extracted from AGENTS.md on 2026-08-14 so the
manual could stay short while nothing was lost. Do not add new rows here unless
you are also reflecting the resulting invariant in the condensed guard rails in
AGENTS.md.

The ledger table below has one row per entry: | Sequence | Symptom / finding | Root cause | Fix | Guard now required |.

## Chronological regression ledger

| Full-frame GIF push was ~10 ms over the wire floor (2026-08-17, built + flashed) | 466x466 full-frame push measured 21 ms in-loop against a ~13 ms wire floor; the perf push mean was 23.5 ms. Instrumented breakdown showed the byte-swap copy taking 16.2 ms (79% of the push) and DMA only ~4-6 ms. | The fused swap loop loaded/stored every pixel through `gif_u32_alias_t`, a `__aligned__(1)` typedef. Xtensa has no unaligned 32-bit load (`l32i` faults on a non-4-aligned address), so every nominal word access compiled to 4 byte loads + combines: ~10x the instructions of a plain memcpy (16.2 ms vs 5-7 ms for the same 434 KB stream). The `__aligned__(1)` alias is the anti-optimisation: it tells the compiler the pointer may be byte-aligned, so it can never emit word access. | Split the copy from the swap: one `memcpy` per strip (full-width strips collapse to a single contiguous copy; narrower strips keep per-row copies), then a tight 64-bit in-place byte-swap on the internal DMA buffer. The xfer buffers are now allocated with `heap_caps_aligned_alloc(8, ...)` (MALLOC_CAP_DMA alone only guarantees 4-byte alignment, which would make the direct `uint64_t*` access UB). A memcpy-per-8-byte variant of the swap measured ~2x worse (42 ms) from per-word call overhead and must not be reintroduced. Hardware-verified: full-frame push 21 ms -> 15.5 ms in-loop (copy 16.2 -> 7.9 ms, wire DMA ~6 ms), perf push mean 23.5 -> ~17.7 ms, cadence at 30 ms delay ~18.7 -> ~21 FPS. Colors unchanged, no panics, web healthy. | Do not reintroduce a per-pixel/per-word byte-swap through `gif_u32_alias_t` (or any `__aligned__(1)` type): on Xtensa it compiles to byte-wise access and costs ~10x a memcpy. The push strip copy must be memcpy-first then an aligned in-place swap on the internal DMA buffer. |
| GIF playback could run faster than the authored frame delay (2026-08-16, built + flashed) | Asked whether a GIF can play faster than intended: yes. The pipelined path set the timer period to `delay − last_push`, so a frame's on-screen time was `D − last_push + next_push`. A heavy full-frame push (large `last_push`) followed by a tiny delta push (small `next_push`) displayed that full frame for e.g. 13 ms against a 30 ms authored delay (~2.3x faster). A secondary race: `ms_delay_next` was read after `sem_next_decode` was given, so the Core-1 decoder could overwrite it with frame N+2's delay before the read. | The `D − last_push` compensation assumed every push takes the same time; variable push durations (full vs delta frames) made the compensation overshoot. | Deadline pacing: the next push now starts no earlier than `end_of_this_push + D`. Since the timer period is measured from the callback start and the just-completed push took `last_push_us`, the period is `D + last_push` — guaranteeing on-screen ≥ D (never faster; on average one push-duration slower, the accepted tradeoff). The frame delay is captured before waking the decoder. Hardware-verified: bulb.gif plays at its authored 30 ms cadence, 120/120 direct pushes, no panic. | The pacing guard is `period = D + last_push`, never `D − last_push`. Capture `ms_delay_next` before `xSemaphoreGive(sem_next_decode)`. |
| Post-audit fix round for the GIF playback branch (2026-08-16, built; hardware soak pending) | An independent audit of the `gif-playback-fps` diff found: (H1) the `initialize()` re-open teardown kept the double-free + fixed-15 ms decode-race the destructor fix had removed (latent — no caller re-opens a loaded widget); (H2) the `is_full_opaque` canvas-copy skip read the PREVIOUS frame's rect, so a partial/transparent frame after a full-opaque frame composited over a two-cycles-stale buffer; (H3) `sem_next_decode` was given before the push rect was read, so the Core-1 decoder could overwrite `gif->iX/iY/iW/iH` for frame N+2 while Core-0 pushed frame N+1 with a mismatched window; (M4) the LVGL fallback could not blend the RGB565_SWAPPED source (`LV_DRAW_SW_SUPPORT_RGB565_SWAPPED` = 0) so a refused direct push (e.g. regionDBuf toggled off, which frees the scratch strips) rendered a blank GIF; (M5) the fused LZW 8-pixel-wide stores could run up to 7 pixels past the framebuffer on the final string; (M6) an odd canvas origin (centered GIF < 466 px) made `r_fx` negative and the `read_fb` source offset wrap. | (H1) `initialize()` copied the pre-fix teardown; (H2) the skip keyed on stale geometry; (H3) the semaphore ordering race; (M4) the branch pre-swapped the palette to big-endian (RGB565_SWAPPED) but LVGL's sw renderer has no SWAPPED blend path, so the fallback path diverged from main; (M5) unbounded wide stores; (M6) round-down clamp below an odd origin. | (H1) `initialize()` now mirrors the destructor (snapshot fb0/fb1 before free, NULL `pFrameBuffer`, `decode_done` handshake). (H2) the canvas copy is now unconditional. (H3) the decoded rect is snapshotted into `gifobj->last_fx/fy/fw/fh` before `sem_frame_ready` and `invalidate_frame` takes the snapshot. (M4) reverted to a little-endian RGB565 framebuffer: palette loads store LE, the widget uses `LV_COLOR_FORMAT_RGB565`, and the direct push re-added the fused LE→BE byte-swap (restoring main's proven fallback; the swap cost is proportional to the dirty rect, so delta frames keep 60 FPS). (M5) framebuffers now carry a 16-pixel pad (`GIF_FB_PAD_BYTES 32`) while `imgdsc.data_size`/stride stay exact. (M6) the clamp rounds up to the next even >= origin and zero-area rects fall back to LVGL. The canvas copy before each decode is unconditional. Fused wide stores stay within the padded framebuffer. Odd origins round up to even. Re-open teardown must use the `decode_done` handshake and snapshot-before-free. |
